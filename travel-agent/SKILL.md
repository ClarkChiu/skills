# 旅行規劃 agent

台灣出發自由行的領域知識庫。**本檔是路由**：判斷該做什麼、該讀哪一份 reference。細節在 `references/`，需要時才讀，不要一次全載。

交付文件的**產生管線與檢查**歸 `single-source-docs`（那份管「文件會不會出錯」，不管旅遊內容）；
收工驗證歸 `verify-before-done`；繁中排版歸 `chinese-typography`。

## 收錄規則（新增內容前先讀）

1. 只收**跨旅程可重用的原則與教訓**。
2. 當次查證的數字／方案名／保費／罰則細節，留在**該旅程專案的 md**；skill 內只能以「範例」引用，且**必附年份＋目的地**（如「越南 2026」）。沒掛年份目的地的具體數字＝違規，改寫或刪。
3. 每次旅程結束把新教訓分流：領域原則進 `references/` 對應檔、查證細節進專案 md、交付機制類進 `single-source-docs`。
4. **專案端推翻任何結論時，同一輪回頭檢查 skill 有沒有同一個錯。**修正是雙向的：grep `references/` 有無同源敘述，有就一起改，並在 `sources.md` 的「已知的錯誤來源」登錄一筆。**只修專案不修 skill，等於把錯誤留給下一趟繼承**（實案：換匯數字在專案改對了，skill 的同一段錯了一整輪沒人發現）。
5. **易變事實一律標「每趟重查」**：法規、簽證規則、行李限制、假日、費率、官方網址都會變。寫死＝下一趟踩雷。
6. **每一格的驗收問句，答案必須是一個具體的值**（數字、日期、網址、店名、一句可以直接貼進交付文件的話）。
   問句如果能被「有」「已注意」「已考慮」回答完，那格就是空的——重寫問句，或直接刪掉那一格。
   這條是防止清單變成打勾儀式的唯一有效機制。
7. **這是通用技能，不是某一趟的紀錄。**寫任何一條之前先問：**換一個目的地、換一種旅程，這句話還成不成立？**
   - 成立 → 寫成通則，具體數字用「範例（目的地 年份）」引用。
   - 只在某些情況成立 → 明寫**前提**（例：「實名制國家才適用」「陸路口岸不適用」）。
   - 只在這一趟成立 → 不要進技能，留在專案。
   **風險是無聲的**：一直用同一種旅程操練，內容會慢慢長成那種旅程的樣子而沒人察覺。
   定期反向檢查一次：拿一種結構不同的假想旅程（多國、陸路、長住、出差、自駕）走一遍 §1，
   哪幾格答不出來，就是被帶偏的地方。
8. **新教訓要能歸到 §1 的某一格。**歸不進去代表模型缺一格，先補格再收內容；
   但**補格之前先反過來核對**：很可能那件事早就寫在某份 reference 裡，只是 §1 沒指過去。
   （實案 2026/8：以為缺 8 個領域，核對後發現全部早就寫好了，缺的只是目錄。）

## §0 使用者條件

**持久條件**

- 機票慣刷滙豐「旅人輕旅卡」→ 附帶險只保持卡人本人（＋配偶＋未滿 25 歲未婚子女），**同行朋友即使同卡刷也零保障** → 全員加保產險是標配。附帶險為年度活動制，每趟重驗（`insurance.md`）。
- 交付語言：繁體中文台灣用語。

**每趟必問（不要預設答案）**

先讀專案裡已有的憑證（機票、訂房、收據）**推出答案，再拿推論去確認**——
「訂房看起來是 4 位成人、2 間房 4 張分床，對嗎？」比遞一張空白問卷好答太多，
而且確認的成本遠低於回想。憑證沒寫的才問。

問題本身有兩條紀律：

1. **答案會改變交付內容的才問。**檢驗方法：把某一題的答案翻過來、重產一次，
   如果五份文件一個字都沒變，這題就該刪。
2. **答案取決於對方怎麼分類的時候，不能用是非題，要列舉。**
   問「有沒有慢性病用藥」會拿到假的「沒有」——多數人不把安眠藥、避孕藥、抗焦慮藥算成慢性病用藥。

| 問題 | 為什麼要問 |
|---|---|
| 同行人數與關係 | 決定床型需求，也決定信用卡附帶險保得到誰 |
| 出發地（住哪個縣市） | 決定機場接駁可行解；中南部加清晨班機是另一種問題 |
| **每個人的護照效期到哪天、英文姓名拼法** | 這題**可以用算的**（護照到期日減回程日）卻最常漏。未成年人的護照效期只有成人一半；剛換發新護照的人，簽證可能綁在舊護照號碼上 |
| SIM 需求：手機支不支援 eSIM、要幾張 | 張數不等於人數（可能幫別人代買） |
| **固定要吃的藥**（列舉：安眠藥、避孕藥、精神科用藥、心血管、糖尿病、止痛藥） | 很多國家對特定成分限天數並要求英文證明；問法要列舉，不能只問「有沒有慢性病」 |
| 飲食限制（素食、宗教飲食、食物過敏） | 東南亞的魚露蝦醬花生無所不在；漏問等於餐廳清單重做。過敏是會死人的等級，不是偏好 |
| 體能與行動狀況（含長者、幼兒、孕婦、行動輔具） | 決定住宿樓層與電梯、每天走多遠、機上特殊需求的申請期限（多為起飛前 24–48 小時） |
| **這趟會不會租機車或汽車** | 比潛水常見一個數量級，而且是最容易在毫無自覺下違法的一項（`customs-culture.md` 四） |
| **會不會做水上、高空、潛水、登山健行類活動**（列舉：浮潛、水肺潛水、衝浪、飛行傘、高空彈跳、**登山、健行、攀岩、鐵索攀登**） | 這是保單除外責任的主要觸發條件，選保險前就要知道。**「登山健行」一度漏在這串列舉之外**，而漏掉的後果不是少問一題，是拿到一個假的「沒有」——照舊版問句，一個要爬 4,095 公尺的人也會誠實回答「沒有做水上高空潛水活動」。這正是本表「列舉優於是非題」那條規則自己要防的錯 |
| **住不住非旅館**（親友家、短租公寓） | 有些國家要辦外國人居留申報，旅館會代辦、非旅館不會 |
| 預算框架與行程調性 | 決定取捨基準 |

**還要問一題：這趟是哪一種旅程。**下面每一列都會改變 §1 好幾格的答案，而且是**在規劃初期就要知道**，
事後才發現等於整份重做。預設是「單一目的地、直飛、來回」——只要不是這一種，就照對應那列補查。

| 旅程類型 | 會改變哪幾格 |
|---|---|
| **多國或多城** | 簽證要**逐國各查一次**（不能查一國就套全部）；保險的地區範圍與天數；每一段航班的行李規則各自認；要準備多套貨幣 |
| **中間有轉機或過境停留** | 轉機國可能要**過境簽**；免稅液體在轉機點會再過一次安檢（要防拆封袋＋48 小時內收據）；行李直掛到底還是要領出來重掛；轉機時間夠不夠 |
| **陸路跨境** | **電子簽常常只認空路口岸**，陸路口岸另有清單；落地簽的規則與空路不同；沒有航空公司幫你檢查證件，被拒絕的風險自己承擔 |
| **長住（超過一個月）** | 居留申報；處方藥的天數上限一定會踩線；保險的單次天數上限；簽證要換類別 |
| **出差、商務** | 可能要邀請函與商務簽；收據與報帳格式；公司的差旅風險規定可能覆蓋你自己的選擇 |
| **以自駕為主** | 駕照在當地承不承認（`customs-culture.md` 四）；租車保險的自付額與碰撞險；事故處理程序；當地道路法規 |

⚠️ **目前明確不涵蓋的類型**：以郵輪或長途鐵路為主的旅程、南半球反季節的行程結構。
這兩類的時間與風險結構跟現有內容差太多，沿用會出錯——**要用之前先當成全新領域重查一次**，
不要假設這份技能已經想過。誠實標出來，比假裝通用安全。

**哪些答案會過期，速度不一樣**——不要把它們當成同一批資料一次問完就永久沿用：

| 幾乎不變 | 過敏、血型、飲食信仰 |
| 幾年一變 | 體能與行動狀況、護照（十年期） |
| **每趟必驗** | 護照效期、信用卡附帶險（年度活動制）、保單與館處電話、同行者名單 |
| 每趟重建 | 這趟的活動類型、住宿型態、預算 |

上面那三題粗體的（活動、租車、住宿型態）是**行程的屬性不是人的屬性**——
行程排完之後可能改變答案，所以行程定案時要回頭再驗一次，不能只在開頭問一次。

## §1 該查什麼、什麼時候查

一趟旅程有**四個時間段**，每段要問的事情不一樣。只做「出發前」那一段，回國後那一段就會整段掉出去
（實例：登革熱的潛伏期跨到回國之後，但「行前清單」在字面上就抓不到它）。

**規劃初版時就整張表逐項過一次。**每一格的驗收標準是同一條：
**答案必須是一個具體的值**（數字、日期、網址、店名、一句能貼進交付文件的話）。
如果一格可以用「有注意」「已考慮」回答完，那格就是空的，要重寫問題或刪掉。

## §2 預訂時序管理

**每個要預訂的項目都記三個時間點，缺一個就會出事：**

1. **開放預訂時點**——檔期未公布的表演、季節限定活動：規劃當下訂不到，之後也**沒人記得回頭訂**。要進 watch list。
2. **建議下訂時點**——旺季、連假、熱門餐廳的實際額滿速度。
3. **免費取消／全額退款期限**——過期＝錢直接沒了，而行程變動往往發生在期限之後。

這三個時間**要進行程表與行事曆提醒，不是寫在備註欄**——備註欄不會提醒任何人。取消政策分級標註：不退不換（表演票）／有期限的免費取消（訂房）／no-show 扣卡（餐廳）。

簽證與保險的期限同理回推（`visa-documents.md`、`insurance.md`）。

## §3 審查紀律（硬性守則）

一份像樣的行程交付，sub-agent **至少分兩支獨立跑、不得互看對方輸出**。實證有效：查證支抓到簽證工作天期限，順暢度支抓到抵達日過載——兩者互不重疊。

**查證支**必查：日期 × 星期 × 公休交叉驗證／算術與加總／連結有效性／**每個數字的來源層級**（一手法條 > 官方 FAQ > 官方新聞稿 > 媒體 > 部落格）／易變事實有沒有標「每趟重查」。輸出格式：逐項「通過／不符／查不到」＋出處。

**兩個會讓「已查證」變成假的陷阱**（2026/8 神山實案，兩個都是覆核者抓到的）：

1. **同一個觀測拿去核對自己，不算驗證。** 從某網站推出一個數字，再回頭看同一個網站，當然對得上。
   檢查方法：問「如果我的推估本來就錯，這次查核有沒有可能發現？」答案是「不會」就重做。
   （實案：從訂位日曆推出「可訂範圍約 367 天」，再去同一個日曆看，寫成「推估得到驗證」。
   而且單次觀測分不出那是滾動窗口還是固定截止日——若是後者，隔天所有推算的開放日整排錯。）
2. **兩個網站可能是同一家公司。** 引用第二個來源之前，**先看它的頁尾寫誰經營的**。
   （實案：某條步道的里程當成有兩個來源，頁尾一看兩邊都是同一家旅行社；
   而主管機關與當地旅遊局其實從未公布過這個數字。）

推論：**易變數字寫成「觀測到的值＋觀測日期」，不要寫成天數或通則**
（寫「最後可訂日 2027-08-13（2026-08-11 查）」，不要寫「可以提前 367 天訂」）。

**順暢度支**必查：直接照 `itinerary.md` 第七節的逐日檢查表跑（骨架、主錨點數、折返與跨區、餐點堆疊、緩衝、室內替代方案、頭尾兩天回推、連續高強度、夜場隔天減量）。輸出格式：逐日逐項，問題要指到「哪一天哪一段」。

這是 `single-source-docs` 收工流程第 3 步（獨立對抗式 review）在**行程交付**上的具體化。相關標準：`itinerary.md`（節奏與動線）、`calendar-weather.md`（雨季結構）、`transport.md` 第一節（頭尾兩天可用時間回推）。
