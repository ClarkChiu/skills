# 中文 AI 寫作痕跡（臺灣）

中文文章用這份。它是英文版規則（rules-en.md）的中文版：共用的規則直接沿用，跟語言有關的換成中文，再補上臺灣繁體中文特有的痕跡。整理自維基百科的「AI 味」指南、數位時代和經理人的報導、翻譯腔資料、中國術語表（來源見 attribution.md）。

**寫法要求**：改完要是清楚、簡單、像人在講話的中文。不要簡寫，不要文謅謅，不要中英夾雜。

## 一個最好用的判斷法

AI 中文的核心毛病是 **抽象、對稱、沒有實例**：很愛談意義和價值，句子愛重複同一種句型，但少了具體的時間、地點、人名、數字、和可查證的細節。

快篩法：**「這句話換個主題還成立嗎？」** 把句子裡的主詞換成別的東西，如果照樣講得通，就是空話。

拿「這款**工具**展現了 AI 的潛力」來舉例：把「工具」換成「手機」「相機」「平台」，句子一樣成立。這代表這句話套到哪個產品都對，等於沒講出這個工具任何具體的東西。AI 就是會挑這種「套到哪都對」的講法，所以一句話越通用、越像萬用句，就越可疑。

改寫的方向，是換成只有講這件事才成立的具體內容：

- 空話：這款工具展現了 AI 的潛力。
- 具體：這款工具能把一小時的會議錄音，三十秒整理成一份逐字稿。

## 第一部分：和英文版共用的規則

這些規則跟語言無關，中文一樣適用。細節可對照英文版的編號，這裡只列重點：

- 第 2 條，一句話收尾和戲劇短句（**強痕跡，出現一次就改**）：
  段落最後單獨一句重講前面的話（「這才是真正的關鍵。」），或一連串短句製造戲劇感。
  - 也包括**替讀者解讀剛看完的例子**：舉完例子、講完一段場景或一個數字，馬上補一句「這說明了……的重要性」「訊息很清楚：……」「這是一堂關於耐心的課」。讀者剛看完，自己看得懂，刪掉。這句如果補了例子本身沒有的事實或後果，就留著。
- 第 13、15、16、17 條，內容灌水：
  把小事說成大事、硬補一段「挑戰與展望」（第 13 條）；用「彰顯著、象徵著、推動著」這種詞尾堆假深度（第 15 條）；宣傳腔（第 16 條）；模糊歸因（「專家認為」「相關研究指出」卻不給來源）、硬強調它很有名、廣受報導（第 17 條）。
- 第 14 條，模糊的關聯：
  「與某公司有關」「和這個計畫相關」卻不講到底是什麼關係。
- 第 6 條，三段式：
  硬把東西湊成三項，看起來比較完整。
- 第 5 條，跟不存在的人爭辯：
  「我不是說……」「要說清楚的是……」，但前文根本沒人這樣主張。
- 第 11 條，被動句和沒有主詞的句子（**單獨出現不算**）：
  「無需設定」改成「你不用設定」。
- 第 19 條，內嵌標題的條列：
  每點都是「**粗體標題：**一句廢話」。
- 第 24 條，標題後先補一句空話：
  標題下面那句通常只是重講一次標題，沒有資訊。
- 第 22、23 條，客服腔：
  「希望這對你有幫助」「當然！」、諂媚話（第 22 條）；說「我的資料只到某年某月」、查不到就用猜的補上（第 23 條）。
- 第 9 條，限定詞疊太多、不敢說死（**單獨出現不算**）：
  「或許可能在某些情況下」這種一層疊一層的保留。
- 第 3 條，假裝有洞見：
  「問題的核心在於」這種講法。
- 第 4 條，只預告不做事：
  「讓我們深入了解」這種講法。
- 第 25 條，寫文件本身，不寫文件要講的東西：
  文件要描述東西本身，不是描述文件自己。常見三種：
  - 寫這次改了什麼（「這是為了取代舊的……而新增的」）。只有變更紀錄、版本說明、升級指南這類講改動的文件才該提舊版。**技術文件最常犯。**
  - 交代這份文字怎麼做出來、資料從哪裡來（「以下數字整理自各廠商官網，無法確認的部分已標註而非臆測」）。讀者查得到的出處留著；你怎麼做事的過程刪掉。會改變讀者該怎麼做的但書留著。
  - 描述讀者自己看得到的版面（「下表比較了……」「本節依負責人排列」）。讀者自己推不出來的慣例才講，而且只講一次。只有一句這種話**單獨出現不算**。
- 第 26 條，替讀者重講他早就知道的事（回覆訊息才適用）：
  一則簡短的回覆，先重述問題、走一遍診斷、擺出證據，最後一句才講決定；或附上查詢語法、指令、一串數字，只為了證明方案行得通；或把對方自己寫過、已經同意的背景再講一遍。對方本來就知道來龍去脈，重講不但沒有新資訊，還把重點埋到最後。每句單看都通順，所以逐句清理抓不到它。
  改法：**先講決定**，只留會影響對方同不同意的理由，通常是一件他還不知道的事，加上他動手需要的連結。診斷過程和方案可行的證明，放進後續的工單或文件。審查者提起一個話題，不等於要你交一份完整報告。
  但書：看得到前後對話、或文字明顯是一則回覆時才動手；看不出來就問，或不要動。這條講的是整則回覆的**順序**；開頭的罐頭鋪陳句（「在開始之前，我們先來了解一下……」）見 A-2。
- 不要亂改的情況、和人類寫作的特徵：
  見第四部分。

## 第二部分：英文規則換成中文

| 英文版那一條 | 中文版怎麼做 |
|---|---|
| 英文 AI 慣用詞（第 12 條） | 換成中文裡空泛的詞，清單見下方 D |
| 英文少用「是」（第 18 條） | 中文對應：濫用「作為、堪稱、標誌著、象徵著」去取代一個簡單的「是」 |
| 否定平行句（第 1 條） | 中文一樣有，而且是**最強的 AI 訊號**（見下方 C） |
| 句首重複（第 7 條） | 中文對應：同一種句型連發（見下方 B 最後一列） |
| 英文標題大寫、英文連字號（第 20、10 條） | 英文專有，中文不用管 |

## 第三部分：臺灣繁體中文特有的 AI 痕跡（重點）

### A. 罐頭開場白和收尾

| AI 範例 | 自然寫法 |
|---|---|
| 值得一提的是、值得注意的是、眾所周知、不難看出、由此可見 | 直接講重點。這種開場多半整句刪掉 |
| 總的來說、綜上所述、整體而言、總結來說 | 結尾給一個具體判斷或下一步，不要再覆述一遍 |
| 老實說、說真的、最妙的地方在於、而最棒的部分是 | 拿掉賣關子的語氣，直接說那件事 |
| 你並不孤單、你的觀察很敏銳、準備好深入了嗎 | 一般文章不用安撫讀者的情緒 |

### A-2. 對話助理罐頭語（回覆訊息用的，不是文章用的）

上面 A 收的是**文章腔**的起手式。這一節收的是**對話回覆**的起手式與收尾——兩者不一樣，
中文助理最常犯的其實是這一類，而它們在英文的清單裡多半沒有對應概念。

| AI 範例 | 自然寫法 |
|---|---|
| 以下是……、以下為你整理幾點、以下分成三個部分說明 | **中文助理最高頻的一個。**直接給第一項，清單自己會說明它是清單 |
| 需要我幫你……嗎？、要不要我再幫你補充說明？ | 該做的事就做掉；真的要對方決定，就把選項講明白讓他選，不要把工作丟回去 |
| 我來幫你處理、我會先……然後…… | 只預告不做事。直接做，或直接講結果 |
| 好問題！、這問題問得很好、感謝你的提問 | 整句刪掉。稱讚提問是最明顯的助理腔 |
| 讓我來幫你看看、讓我先確認一下 | 同上，刪掉直接看 |
| 看了你的程式碼之後……、從你提供的資訊來看…… | 刪掉。你看了是理所當然的 |
| 要回答你的問題的話……、針對你剛剛提到的問題…… | 刪掉，直接回答 |
| 在開始之前，我們先來了解一下……、要理解這點，得先從……講起 | 答案前的整段鋪陳。先給答案，需要背景再補 |
| 你遇到的這個狀況其實蠻常見的、這是很多人都會踩到的坑 | 安撫語。刪掉，直接講怎麼回事 |
| 明白了！、了解～、沒問題！、當然！ | 單獨成句、不帶資訊的確認，刪掉 |
| 有任何問題歡迎再問、如果還有不清楚的地方隨時告訴我 | 收尾客套，刪掉 |
| 希望對你有幫助、希望以上資訊對你有所幫助 | 同上 |
| 祝你順利！、加油！、祝開發愉快 | 中文特有的祝福式收尾，刪掉 |
| 糟糕！、哎呀、不好意思，好像出了點問題 | 報錯不要帶情緒。直接講位置、原因、怎麼修 |

**但書：**「先講結論：」如果後面真的接結論，那是好寫法，不要砍；只有當它後面接的是
鋪陳時才算罐頭語。同理「簡單來說」放在句中做總結是自然的，放在開頭當緩衝才要刪。

### B. 結構腔（骨架太僵硬）

| AI 範例 | 自然寫法 |
|---|---|
| 首先…其次…再者…最後、第一…第二…第三 | 用「先…再…」或直接分段，不用每段都標「首先、其次、最後」 |
| 一方面…另一方面、不僅…而且、既…又 | 拆成兩句講，或用「而」「也」帶過 |
| 儘管面臨挑戰，但未來可期、展望未來 | 有具體後續就寫具體，沒有就不要硬補一段展望 |
| 句型連發：這款工具很直覺，這款工具很強大，這款工具很可靠 | 一樣的句型連發好幾句像廣告標語，併成一句：這款工具直覺、強大又可靠 |

### C. 否定平行句（最強的 AI 訊號）

| AI 範例 | 自然寫法 |
|---|---|
| 不是甲，而是乙｜不只是甲，更是乙｜這不僅僅是…，而是… | 把對比拆掉，只留要講的那件事。例：「她不是在哀悼過去，而是在告別自己的童年」→「她其實是在跟自己的童年告別」 |

維基百科的「AI 味」指南和數位時代，都把這種對比句式列為頭號破綻。

### D. 空泛的詞和「假深度」

| AI 範例 | 自然寫法 |
|---|---|
| 至關重要、深入探討、深入研究、彰顯、突顯、賦予、見證了、奠定基礎 | 講具體影響：「至關重要」改成「少了它會怎樣」；「深入探討」改成「來看」 |
| 此外、然而、因此（每段開頭都來一個） | 中文靠語序就接得起來，多數可以刪 |
| 名詞化的假深度：自我的探索、情感的流動、成長的旅程 | 把名詞拆回動詞：找自己、哭了、面對真話 |

### E. 中國商業術語（在臺灣寫作裡特別明顯）

這類是中國網路公司的內部術語，不是臺灣日常用語，一出現就高度可疑。（注意：這是**用詞風格**問題，歸這份規則管；至於「視頻換成影片」這種**地區用詞**（臺灣和中國用法不同的詞）的替換，歸排版層管，見第五部分。）

| 術語 | 臺灣自然寫法 |
|---|---|
| 賦能 | 幫助、讓…能夠、支援 |
| 抓手 | 著力點、切入點、方法 |
| 閉環 | 完整流程、形成循環 |
| 顆粒度 | 細緻程度、精細到什麼層級 |
| 對齊（指共識的時候） | 取得共識、講清楚、講好 |
| 拉通 | 串起來、整合、協調 |
| 沉澱（指累積的時候） | 累積、留下 |
| 賦予、打造、助力、深耕 | 給、做出、幫忙、長期投入 |
| 心智、打法、裂變、藍海 | 認知、做法、擴散、新市場 |

### F. 宣傳腔和誇飾

| AI 範例 | 自然寫法 |
|---|---|
| 打造一站式體驗、全方位賦能、深度整合 | 做、建立；刪掉「全方位、一站式、深度」這種沒有資訊量的修飾 |
| 把小商場說成「文化地標」「凝聚社區的燈塔」 | 照它本來的規模講：就是一間商場 |

### G. 翻譯腔（語法的問題）

| AI 範例 | 自然寫法 |
|---|---|
| 進行了優化、進行了處理、作出決定、做出反應 | 直接用動詞：優化、處理、決定、反應 |
| 可擴展性、穩定性、可讀性（一句塞好幾個） | 口語拆開：能不能擴充、穩不穩、好不好讀 |
| 工具們、產品們、這些客戶們、三個學生們 | 「們」只接在「人」後面（老師們、醫生們可以）；東西不加（工具、產品）；已經有「這些、三個」就別再加（這些客戶、三個學生） |
| 作為一個丈夫，他十分深情 | 他是個深情的丈夫 |
| 他是有名的作家之一 | 他是位有名的作家（刪掉「之一」） |
| 他的意見不被人們接受 | 大家都不接受他的意見（少用被動） |
| 當你寫完報告的時候，把它寄給我 | 報告寫完後再寄給我就好 |
| 他如此疲憊，以至於睡著了 | 他累到睡著 |
| 主要地被視為、十分地深情 | 拿掉多餘的「地」字 |

## 第四部分：不要亂改（看起來像 AI，其實是自然的中文）

- **正常的連接詞**：「然而、因此、此外」本身沒問題，只有**每段開頭都用、用得很密**才是痕跡。單獨一句不要動。
- **技術或學術語境的名詞化和被動式**：規格書、論文裡的「穩定性、可擴展性」「被定義為」是這個領域的慣例，不是腔調。**只有口語、行銷、一般文字才算痕跡。**（這點對使用者很重要，他常寫技術文件。）
- **真正的步驟教學**：食譜、安裝步驟用「首先…其次」是對的，不要拿掉。
- **本來就有三個**：東西本來就有三項，列三項沒問題。要砍的是那種為了湊整齊、硬擠成三項、內容又空的句子。
- **「打造、品質、資訊」在臺灣是正常詞**：該砍的是「賦能、抓手、顆粒度」那種術語，這些不用動。
- **痕跡分強弱**：強痕跡出現一次就改，包括 C 否定平行句、A-2 對話助理罐頭語、第一部分的第 2 條一句話收尾。其餘痕跡，尤其是這一部分列的正常連接詞、被動句、限定詞，要**好幾個一起出現**才動手，不要看到一個就咬定是 AI。

## 第五部分：交給排版層（chinese-typography）做的，這裡不要做

這份規則只管文風（用詞、結構、修辭）。下面這些是排版層的工作，**不要在這裡碰**，跑完這份規則再交給它（銜接方式見 SKILL.md）：

- 標點的全形半形、引號改成「」、中文和英文之間補空格。
- 破折號：中文的破折號「──」是正常標點，**不要照英文第 8 條那樣砍掉**，交給排版層判斷。
- 簡轉繁、地區用詞替換（視頻換影片、軟件換軟體、質量換品質、屏幕換螢幕…）：這是排版層的 OpenCC 和 vocab_fixes 在做，這裡不要重複。

### 界線的細節：改寫整句，不是只換一個詞

「地區用詞不要碰」這條，只有在那個詞單獨出現、句子其他地方都不用改的時候才乾淨。如果那個詞卡在一個本來就要改寫的句子裡，情況不一樣：

- **可以**：為了讓文風自然，把整句改寫，就算那個地區用詞跟著消失也沒關係。例如「檢索信息」太正式、有 AI 腔，改成「查資料」是對的。這是改寫文風，不是越界。
- **不要做**：句子其他地方都不動，只挑一個詞做地區用詞對換。例如整句不改，只把「信息」換成「資訊」。那是排版層的機械替換，交給它做。
- 一句話分辨：**整句重寫、那個詞自然跟著變，可以；句子不動、只挑一個詞對換，交棒。**

提醒：不要因為怕動到地區用詞，連「檢索」這種該口語化的正式詞也不敢改，那會改得太保守，留下一個僵硬、有 AI 腔的句子。寧可把整句改自然。
