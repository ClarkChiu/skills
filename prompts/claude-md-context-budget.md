# CLAUDE.md context 預算／結構稽核提示

**用途**：和「規則衛生」是不同軸——這條不管規則對不對，只管**載入成本與結構**。CLAUDE.md 每回合
整檔載入＝每回合的固定 token 稅。這份提示量化臃腫，標出哪些該移到按需載入的位置或收成 skill，
**只回報、不改檔**。對抗「CLAUDE.md 越長 → 每回合 context 稅越重 → 把模型資源耗在用不到的規則」。

**怎麼用**：手動貼，或由內建 `schedule` 按需/每月跑（接線見 `prompts/README.md`）。
**語言**：報告用臺灣繁體中文。

**官方依據**：Anthropic memory 文件——`@import` 只是「組織」用，**不省 context**（啟動時整檔展開）；
要真正省，用帶 `paths:` frontmatter 的 `.claude/rules/`（只在碰到相符檔案才載入）或子目錄 CLAUDE.md
（按需載入）。把「永遠用得到」留在根 CLAUDE.md，「只有特定任務/路徑用得到」往外移。遷移到 skill 的
做法參考 Cem Karaca（把 42k→1.9k token）。

---

```
讀取我的 CLAUDE.md 與所有設定，做一次「context 預算與結構」稽核——不評斷規則內容對錯，
只看載入成本與該放哪。只輸出報告、不修改任何檔案。

1. 量化：先用 bash 量 CLAUDE.md 行數與粗估 token（約 行數×字數密度），並按段落列出各段大小，
   標出最肥的 3 段。對照 ~150–200 行 / 健康 token 目標。

2. 對每段/每塊規則，判它屬於哪一類載入需求：
   - 【根 CLAUDE.md 留著】永遠用得到、跨所有任務（語氣、語言慣例、核心行為準則）。
   - 【移到 .claude/rules/（path-scoped）】只在碰到某類檔案/路徑才需要的規則
     （例：只在改某語言/某子系統時的規則）——加 `paths:` frontmatter，按需載入才不每回合付稅。
   - 【移到子目錄 CLAUDE.md】只在某子目錄工作時才需要的規則。
   - 【收成 skill】成段、有觸發語境、只有特定任務要用的整套流程（例：某個產生器/檢查流程）——
     比塞進 CLAUDE.md 每回合載入更省，且能被觸發式呼叫。

3. 防呆：我的 CLAUDE.md 是**刻意可攜**的（隨 git/APM 跨機帶走），跨工具分發由 APM compile
   負責。任何「移出去」的建議都要維持 APM 相容、且不破壞可攜性——不確定就標出來讓我判斷，
   別假設我用某個只在單機存在的機制。

最後提供（臺灣繁體中文、只輸出報告、不改檔）：
- 各段大小排行＋總行數/估算 token vs 目標
- 搬移建議表：哪段 → 搬去哪（rules/子目錄/skill）→ 預估省下多少每回合 token → 信心(高/中/低)
- 留在根 CLAUDE.md 的核心清單（明說為何這些非留不可）
- 任何 APM 相容性/可攜性疑慮，攤開讓我決定

規則：缺證據標假設、不瞎掰；只提議、搬移與重構都等我逐項核可。
```
