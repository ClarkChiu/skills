# handover — 網頁對話交接提示（`handover` 技能的聊天版孿生）

**用途**：在 **claude.ai 網頁對話**（或任何載入不了技能的環境）結束前貼上，把這次對話打包成
下一個全新對話能直接接手的交接文件。是自建 `handover` 技能的聊天模式孿生：技能歸 Claude Code／
OpenCode 用（寫檔＋git 中繼資料）；網頁對話沒有檔案系統，只能靠這份薄提示產出**一段可複製的
Markdown 區塊**，由你貼進新對話當第一則訊息。

**怎麼用**：舊對話收尾時整段貼上 → 審閱產出的交接區塊（錯的交接比沒有交接更糟）→ 複製到新對話，
並照文件清單重新上傳附件。**語言**：交接文件跟隨對話語言。

**方法出處**：與技能版同源，蒸餾自 2026-07-23 的社群做法研究——mattpocock `handoff`（引用不複製）、
softaworks `session-handoff`（區塊骨架＋交接鏈）、HumanLayer ACE-FCA（40–60% 時機律＋審閱閘門）、
jdhodges 交接模板（死路區塊）、Amp 廢自動壓縮改交接（遞迴摘要會失真＝整套做法的立論）。
完整網址與取捨理由見 `handover/references/attribution.md`。

**與技能版的差異**（原理見 `handover/SKILL.md`）：接手者讀不到你的檔案，所以「引用不複製」反轉——
關鍵成品（定稿文案、規則清單、結論）要**內嵌**在區塊裡；其餘改成「請重新上傳某檔」。沒有 git，
中繼資料改記日期與已上傳過的附件。

---

以下是提示本體（整段貼上）：

```
我準備結束這個對話、開啟一個全新對話接手。請根據「這次對話實際發生的內容」，產出一份交接文件，
輸出成單一 Markdown 區塊，讓我可以整段複製、貼進新對話當第一則訊息。

嚴格規則：
- 假設接手的對話完全沒有本對話的記憶，也「讀不到我的任何檔案」——所以本次對話定稿的關鍵成品
  （文案、清單、結論、程式碼片段）要直接內嵌在文件裡；引用不到的檔案，改列「需重新上傳」清單。
- 文件開頭附中繼資料：今天的日期，以及本對話曾上傳過的附件清單。
- 只寫本對話中確實發生、確實決定過的事。沒討論過的不要腦補；不確定的放進「待決事項」。
- 區分三種狀態並明確標示：已完成且確認過 ／ 已完成但未確認 ／ 未開始。
- 金鑰、密碼、權杖、個資一律不得出現。
- 產出後停下來讓我審閱，不要自行斷定交接完成。

依序包含：
1. 背景與目標——三到五句電梯簡報：我們在哪、要去哪、為什麼。
2. 目前狀態（最重要）——三態進度；進行到一半的停在哪一步；本對話產出的關鍵成品全文內嵌；
   需要我重新上傳的附件清單。
3. 關鍵決策與理由——決定了什麼、為什麼、否決了哪些替代方案及理由。
4. 踩過的坑與死路——試過但失敗的做法、容易誤判的陷阱。
5. 接手後的第一個動作——單獨一行、具體可執行。
6. 剩餘任務——依依賴順序，每項附確認方式。
7. 驗收標準——「完成」的可驗證定義，避免「運作正常」這種空話。
8. 待決事項——尚未拍板、需要我確認的問題。
```
