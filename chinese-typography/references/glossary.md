# 個人用詞偏好對照表 (Personal Glossary)

寫臺灣繁體中文內容時的**個人用詞釘選與但書**。這是「文件規範」層：靠人遵守，不是腳本自動套用。

## 三層怎麼分工

臺灣中文的用詞與排版偏好分散在三個地方，各管一段，別搞混：

| 層 | 檔案 | 管什麼 | 怎麼生效 |
|---|---|---|---|
| 機械替換（最高優先） | `chinese-typography/user-dictionary.json` 的 `replacements`（個人偏好）／`data/defaults.json` 的 `vocab_fixes`（通用、含凍結版 OpenCC 的引擎缺陷補丁） | 安全、不會撞車的逐字替換（例：`訊令→信令`、`網際網路絡→網際網路`） | `normalize.py` 自動套，凌駕所有規則與 OpenCC |
| 腳本排版規則 | `chinese-typography/references/typography-rules.md` | 盤古之白、全形標點、引號、簡轉繁、異體字…等確定性轉換 | `normalize.py` 自動套 |
| **個人用詞釘選（本檔）** | `chinese-typography/references/glossary.md` | 該用哪個詞、哪些**不能**機械替換的但書 | **靠人遵守**，寫中文時參照 |

判斷規則：**能安全機械替換的詞 → 進機械層（個人偏好放 `user-dictionary.json`，通用的與引擎缺陷補丁放 `data/defaults.json`）；不能機械替換、只能靠人判斷的 → 留在這張表。** 兩者的界線就是「會不會誤傷」——見下表 `潤飾`、`深水區`、`數位人文` 三列的但書。

## 何時讀這張表

- 寫或審臺灣繁體中文內容時（`SKILL.md`、`references/` 規則檔、`evals.json` 說明文字、對話回覆本身）。
- 要把某個用詞偏好「釘死」時：先判斷它能不能安全機械替換——能就加進 `user-dictionary.json`，不能就加進這張表並寫清楚但書。

通則（臺灣繁體中文、不中英夾雜、不簡稱縮寫、能用中文就用中文）寫在 repo 根 `CLAUDE.md` 的〈撰寫語言〉條，是每回合都在的鐵則；這張表只收**通則沒涵蓋的特定詞與但書**。發現新的用詞偏好就往這張表（或 `user-dictionary.json`）加。

### 不能逐字替換的中國用語

下面這些出自 sysprog21/zhtw-mcp（5b385b3d66b1）的對照，2026-10-05 審過、**刻意不收**進機械層：同一個字串在不同語境要換成不同的詞，或會跨詞誤傷。只能靠人判斷。

| 中國用語 | 臺灣常見說法 | 為什麼不能逐字替換 |
|---|---|---|
| 回歸 | 迴歸（統計） | 「回歸本業」「回歸初心」的「回到」義是正當用法，只有統計的 regression 才寫「迴歸」 |
| 身份 | 身分 | 教育部用字是「身分」，但沒有詞界線時「本身份量」「全身份額」這種跨詞組合會被誤改 |
| 篩查 | 篩檢 | 醫學的 screening 才是「篩檢」；「篩查資料」「篩查名單」是一般的篩選檢查，不該改 |
| 黃油 | 奶油 | 也指機械用的黃色潤滑油；而臺灣「奶油」又兼指鮮奶油，換過去未必更清楚 |
| 按揭 | 房貸／貸款 | 名詞、動詞譯法不同（「按揭利率」→「房貸利率」、「按揭買房」→「貸款買房」），不是一對一 |
| 用人單位 | 雇主／用人機關／徵才單位 | 看是公部門還是民間企業，沒有單一譯法 |
| 零假設 | 虛無假設 | 「零假設的前提下」可能是「沒有任何假設」的字面意思 |
| 數學期望 | 期望值 | 會跨詞誤傷：「家長對數學期望很高」裡的「數學」和「期望」是兩個詞 |

**已審定為臺灣自然化、掃描時別再誤報為陸詞**：`躺平`（雖源自中國網路語，但已是常見梗，且常被拿來當品牌／標題名，保留）、`打卡`（觀光書寫已高度普及：打卡點／打卡地標）、`小眾`（品牌／選品語境臺灣常見）。這幾個做「非臺灣語感」掃描時容易被抓，實際已自然化——除非使用者另行指定，維持原樣。

**例外（維持原樣，不套用）**：程式識別字、專有名詞（產品名、人名）、JSON 欄位名、測試輸入樣本——這些是資料不是敘述。
