# 寫錯會出事的文件：用程式產生、用程式檢查

**先講清楚這份技能在管什麼。**它的名字（single-source-docs）講的是**做法**——內容只放一份、其他都由它產生；
真正的目的是**這份文件不能出錯**，因為有人會照著它做事、付錢、或趕飛機。

判斷要不要用它，問一句話：**這份文件寫錯或漏掉，誰會因此做錯什麼？**答得出具體後果就該用。

兩種最常見的死法，只有第一種跟格式數量有關：

1. **手改產出的檔案造成各版本漂移**——改了 HTML 忘了改 Word，Excel 的數字跟摘要對不上，沒人知道哪份才對。
   根治法是：內容只存在一個地方，其餘全部由它生成。你的工作不是同步四份檔，是維護一份資料、按一個鈕重產。
2. **該講的事根本沒進文件**——這一種**跟有幾份輸出完全無關**，只有一份檔案時一樣會發生，
   而且更難發現：漂移至少有兩個版本可以互相對照，缺席的東西連比對的對象都沒有。
   > 實案（2026/8）：整套保險方案是照登革熱風險挑的，但「登革熱」三個字在唯一資料源出現 0 次，
   > 四份交付文件沒有一份叫人帶防蚊液——用風險選了保險，卻沒告訴讀的人怎麼不要用到它。
   > 這個洞跟格式數量無關，是鐵則 6（檢查要問兩個方向）抓到的。

所以：**多格式是常見情境，不是前提。**只有一份輸出檔時，鐵則 1、3、4、6 與落地紀律全部照用。

## 架構鐵則

```
data.py            ← 唯一的資料來源：所有文字/數字/清單/連結都在這
  ├─ gen_html.py   ← import data，產主文件 HTML
  ├─ gen_prep.py   ← import data，產另一份 HTML
  ├─ gen_budget.py ← import data，產 .xlsx（試算表就該是試算表）
  ├─ gen_slides.py ← import data，產簡報 HTML
  ├─ gen_gifts.py  ← import data，產 .md
  ├─ check_*.py    ← 自動檢查：有問題 exit 1，擋下壞掉的交付檔
  └─ build.sh      ← **唯一入口**：把所有產生程式 ＋ 所有自動檢查串起來，並檢查有沒有產生程式漏登錄
```

1. **產出的檔案是唯讀的。** 永遠不手改 `.html/.docx/.xlsx`。要改內容 → 改 `data.py` → 重跑整套流程。手改產出的檔案 = 下次重產就被蓋掉，且與資料來源不一致。
2. **一鍵重產要有一個 runner 檔，不是一串靠記憶維護的指令。**建 `build.sh`／Makefile 當唯一入口，把每支產生程式 與每個檢查都串進去，任一步非 0 就停。**並在 runner 內加漏掛檢查**：掃 `gen_*.py` 的實際檔案清單，比對它有沒有全部登錄——新增第 4 支產生程式卻忘了加進指令字串，那份交付檔就永遠不會被重產，也不會被任何檢查掃到（實案：簡報的產生程式落在流程外，被批次腳本刪掉一整行內容而無人察覺）。
3. **自動檢查要 exit 非零，而且要規定「最小涵蓋範圍」。**光有一個檢查不夠——要問的是「每份交付檔都被掃到了嗎」。最小四類：(a) 排版／在地化 (b) **必填欄位非空、字數下界**（這一類專擋「整段內容消失」，是最便宜也最容易漏的）(c) 算術與加總 (d) **資料來源對帳**：指定欄位的值必須出現在指定交付檔裡。實案：某專案四份交付檔只有一份有自動檢查，.docx 零 assert，結果批次腳本刪掉簡報一整行、版面檢查照樣全綠——因為少一行字只會讓版面更寬鬆。
4. **既有已交付的檔案是 diff oracle。** 重構產生器後，拿新產出的檔案跟上一版 diff——**應為空**（除非你就是要改內容）。這是「我沒弄壞既有東西」唯一可信的證據。

5. **句子也是資料。**（這裡說的「句子」是指寫成一句一句、給人讀的內容，相對於一格一格的欄位。）凡是會被讀者讀到的句子（含簡報口播稿）都放在資料來源裡，產生程式只做版面決策（顯不顯示、顯示哪一段、用什麼字級）。判準很簡單：**同一件事的說法若在兩支產生程式 各出現一次，就該移進資料來源**。只把「數字」收進資料來源、把「解釋數字的句子」留在各支產生程式，擋得住數字漂移、擋不住**說法漂移**——而實務上出事的多半是後者（同一個結論，A 檔說得對、B 檔還是被推翻的舊版）。

6. **檢查要問兩個方向，不是一個。**多數人只做「資料來源裡的東西有沒有進交付檔」（順向），
   漏掉的是「**該講的事有沒有進資料來源**」（逆向）——那是「根本沒想到要查」造成的洞，順向檢查看不到，
   因為缺席的東西不在資料來源裡，沒有東西可以拿去比對。
   做法：列一張**領域表**，每列寫「這件事這趟適不適用、適用的話該出現在哪幾份交付檔」。
   **不適用的必須寫下排除理由，而且理由裡要有數字、日期或網址。**
   這不是在驗證理由正確，是把「隨便寫一句」的成本拉到高於「真的去想一下」——要誠實承認它是摩擦不是驗證。
   排除理由**綁定這一趟、不跨案子沿用**：上一次排除過就一直排除，是打勾儀式最主要的來源。
   （實作上這是同一支檢查程式裡的一個迴圈，不需要另開一支——它和「沒人用到的欄位」檢查是同一個對照的兩邊。）

## 落地紀律（血淚換來的）

- **整套程式放專案內、不要放 /tmp。** scratchpad 會在對話回合間被清空，整套程式會消失、得從逐字稿重建。放 `專案/_gen/`。
- **row 是固定長度 tuple 時，別加欄位。** 若時間軸/表格的每列是 `(a,b,c,d,e,f,g)`，加第 8 個欄位會讓所有 `for a,b,c,d,e,f,g in rows` 解包爆掉。要掛額外資料（徽章、附近店、狀態）→ 用**另一個以關鍵字比對的側表** `{標題關鍵字: 值}`，產生時查，不動 tuple 結構。
- **xlsx 內的 CJK/非 ASCII 以 XML 數字實體儲存**（`à` → `&#224;`）。純文字 grep xlsx 會**漏字、假陰性**。要驗證內容得 unescape 或直接讀 worksheet XML。
- **交付檔要用「實際讀者」的語言，不是你的語言。**專業行話（金融、法律、技術）在給非專業讀者的文件裡首次出現就要加白話註解，或直接換掉。判準不是「這個詞正不正確」，而是「拿到這份文件的人看不看得懂」。**做法是主動掃，不是等人抓**：交付前用一份行話候選字表（該領域的專業術語）grep 一遍資料來源與各支產生程式，逐個問「我媽看得懂嗎」——被連續抓到三個行話時，代表還有第四個——實案：換匯段寫了「水單」，使用者當場問那是什麼，代表要轉傳給朋友的版本更不可能懂。同一份真源產出多種讀者的格式時（內部 docx vs 對外簡報），行話檢查要按最外圈的讀者做。**程式註解不算對外文字**，那裡精確優先、不必白話；要掃的是會進交付檔的字串（含簡報的口播講稿——那是要唸出來的）。
- **讀者算不出來的數字要當場替他算好。**外幣金額附母國幣值、時間附幾點到幾點、距離附走路幾分鐘——
  少了這一步，數字在文件上，判斷不在讀者手上。標註**要用算的不要手打**（放一個換算函式在資料來源，全部呼叫它），
  而且要有一道自動檢查掃「有原始數字卻沒有換算」的字串。
  > 實案（2026/8）：表格的「價格」欄早就有自動換算，所以沒人發現**寫在句子裡**的金額全都沒有——
  > 一加檢查當場抓到 5 處。**會漏的永遠是散在句子裡的那些**，因為版面層的自動換算碰不到它們。
- **同一件事只准有一種寫法——句型如此，符號與用詞也是。**
  *句型*：九條「這段建議叫車」如果各寫各的（有的先講距離、有的先講時段、有的忘了寫車資），
  讀者每看一條都要重新理解一次結構，而且**缺漏會被當成「這條沒有」而不是「這條忘了寫」**。
  先把句型固定下來（誰→為什麼→要多久多少錢），再逐條填。
  *符號與用詞*：同一個意思用兩種寫法，讀者會以為其中一個另有含意。
  > 實案（2026/8）：「≈」與「約」混用——主文件 62 個 ≈ 對 118 個「約」，另一份 13 對 5。
  > 成因是自動換算的樣板寫 ≈、手寫的句子寫「約」，兩邊各自都很一致，合起來才亂。
  **挑白話、唸得出來的那個**（「約」不是「≈」），然後給一道檢查掃另一個，
  **手動維護的檔案也要一起掃**——那是最容易長回來的地方。
- **易變資訊標時效＋來源。** 價格/營業時間/匯率/電話會過期：頁尾註「以官方當日資訊為準」，數字附換算（本地幣＋母國幣），聯絡管道註「出發前再確認」，別把二手查來的號碼寫成「已查證」。
- **排程類一定做「日期 × 星期 × 公休」交叉驗證。** 最常見的錯是把店排到它公休那天。用真實日期回推星期，逐項比對公休日。
- **事實用一手來源核對，不信二手描述。** 影片裡的店 → 逐格看門牌/招牌/收據；別採信網路轉述的店名地址。錯一次整條動線就歪。
- **啟發式單位轉換要「顯性標記守門＋全域稽核」。** 會推斷單位的自動轉換（如「數字 ≥10,000 就當外幣換算」）最脆弱：守門條件優先認顯性單位標記（字串已含 `NT$`/`TWD` 就跳過）。一旦發現誤判，不能只修被指出的那筆——同類輸出全部抓出來反算驗證（實案：62 條換算全查，僅 1 條假）。點修＝假修。
- **用 mutation test 證明「交付檔真的來自資料來源」，別靠讀程式碼判斷。**做法：暫時把資料來源裡的值改成一眼認得出的假值 → 重產全部格式 → 檢查每份交付檔「新值出現、舊值消失」→ 還原。這是唯一能抓出「某支產生程式 其實是硬寫」的方法：實案一次抓到兩處漏——航廈只寫在其中一支產生程式（改了 Word 檔、簡報還是舊的），另一個欄位只有一支產生程式 在用。**注意假值本身要通過自動檢查**（例：排版檢查會擋掉 `MUT-A%` 這種違反盤古之白的字串），用「形狀相同的數值」當假值最省事。
- **檢查的要求要逐份交付檔寫，不要一個標準套全部。**版面有密度上限的交付檔（投影片）不能要求出現完整原文，
  否則會逼出反效果——為了通過檢查把投影片塞爆，違反「一頁一個概念」。正確做法：文件類要求完整原文，
  投影片只要求一個**從資料來源抄過去的關鍵詞**。同一格、兩種要求。
- **檢查程式自己也要被驗一次，不然它就是最貴的裝飾品。**方法就是把 mutation test 用在檢查上：
  故意製造它「應該要擋」的四種情況，看它是不是真的擋。實案（2026/8）四個測試：
  把某個條件翻成 True 但沒定義要檢查什麼、排除理由清空、排除理由改成「應該沒問題吧」、
  從產生程式裡拿掉一整段內容——四種都要擋下來才算數。
  **特別注意「條件成立但沒定義檢查內容」這一種**，它最容易被寫成靜靜通過，而那正是覆蓋檢查要防的事。
- **交付檔要跟原始憑證對帳，憑證「沒說的」fail-loud。** 訂房截圖、e-ticket、收據 PDF 是 source of truth，逐項比對；憑證沒證明的（床型、行李額度）明講「待確認」，別腦補成已確認。標出未知，比假裝已確認安全。
- **狀態一改變，檢查要同時問「新說法在不在」與「舊說法有沒有留下來」。**只問前者會假通過：
  實案（2026/8/7）——簽證從「審核中」變成「已核准」，檢查用核准日「8/7」當關鍵詞，
  而那份還沒更新的檔案裡剛好有一句「預計 8/7 前會有結果」，關鍵詞照樣命中、檢查全綠；
  但那份要轉傳給朋友的檔案還在叫人「8/8 沒消息就上官網查」——**去查一件已經結束的事**。
  做法：對帳表除了「必須出現的字」，再列一組「不該再出現的字」（舊狀態的招牌句），出現就擋。
  **舊說法才是會害人的那個**：新說法漏了只是資訊不足，舊說法留著是主動發出錯誤指令。
- **順向檢查抓不到「同一個事實在交付檔裡出現兩次，一次對一次錯」。**
  它問的是「資料來源的值有沒有進交付檔」——有，通過。它問不出「交付檔裡有沒有另一句自己寫的、講同一件事但過期的話」。
  實案（2026/8/7）：一個表演的檔期同時硬寫在四個地方（時間軸、彈窗簡介、聯絡卡片、預訂表），
  查證後把事實收進資料來源、改好時間軸，自動檢查全綠——另外三處還在說「檔期官方下個月才公布」。
  **做法：把一件事收進資料來源的當下，立刻拿它最有辨識度的幾個字去 grep 所有產生程式**，
  把找到的每一處都改成讀欄位。不 grep 就等於只改了你剛好想得到的那一處。從句子裡抽日期、代碼、金額這種事，
  一旦有兩支程式各寫一套自己的規則，句子一改就同時壞兩處，而最自然的修法是把規則放寬——檢查就是這樣爛掉的。
  實案（2026/8/7）：資料來源已經把簽證日期抽成具名欄位，註解還寫明「取用端只讀欄位」，
  但另一支產生程式仍自己重寫了三條規則；簽證一核准、句子一改，那三條全部失效、整個流程當場中斷。
  **在註解裡寫「不要重複抽取」沒有用**，要讓第二次抽取根本沒有存在的理由——欄位取好、名字取對，別人就不會想自己抽一次。

## 收工流程

每次改完內容：

1. 只改 `data.py`（或對應資料層）。
2. 跑完整流程重新產生四檔，確認自動檢查 exit 0。
3. **開一個獨立的對抗式 review**（見 `verify-before-done`）：找矛盾、算錯、公休撞日、用詞。你自己說「應該沒問題」不算數。
4. 非平凡邏輯留一個可跑的自我檢查（assert：data 有正確進交付檔、側表掛對、連結有產生出來）。
5. 回報時明講：改了哪些檔哪些行、怎麼驗的、檢查是否都 exit 0、交付檔大小。有取捨就講。

## 與其他 skill 的分工

- 繁體中文排版/簡轉繁/台灣用語的自動檢查 → 直接用 **`chinese-typography`**（`normalize.py` + glossary），別自己重寫規則。
- 「驗證再收工、開 review、fail loud」→ **`verify-before-done`**。
- 本 skill 只管**交付文件的產生流程與檢查紀律**（一份資料源、簡短的產生程式、機器擋得住的關卡）；
  上面兩者是它的自動檢查與收工關卡。文件的**內容**歸各自的領域 skill——
  例如「行程該怎麼排」「景點怎麼挑」歸 `travel-agent`，本檔一句都不碰。
