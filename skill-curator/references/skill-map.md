# Skill Map

When evaluating the **duplication** of an external skill, check this map first — see which functional cluster the new skill lands in, and whether an existing skill already covers it. It's also the reference for avoiding internal rework when building/changing your own skills. **After adding or changing a self-built skill, come back and update this map.**

## Functional clusters

### A. External-skill governance (lifecycle pipeline)
- `skill-finder`: read-only search of skills.sh, fetch a candidate's SKILL.md. **Discovery only, never installs.**
- `skill-auditor`: security audit, produces a SKILL AUDIT REPORT. **Must run before installing any external skill.** Optional deterministic pre-pass via the external `skillspector` CLI (NVIDIA, see README external-CLI section) when installed — a clean scan never skips the manual protocol.
- `skill-curator`: orchestrates the two above + relevance + verdict + record. **Research/decision, never installs.**
- `skill-evolve`: report-only scout for keeping self-built skills current, from **two evidence streams** — (1) **upstream drift** (reads each skill's `attribution.md` + `sources.lock`, diffs via GitHub API) and (2) **your own usage** (`scripts/mine_usage.py` mines `~/.claude/projects/*/*.jsonl` for GAP/FRICTION/MEMORY signals). Both feed one report; never auto-edits. Usage-mining idea from microsoft/SkillOpt `skillopt-sleep` + alchaincyf/darwin-skill (methodology only, tracked in its own `sources.lock`; the "optimize half" stays in built-in `skill-creator`). Boundary: vs `solo-think` = outward proposal from usage evidence, not inward reflection to memory; vs `skill-creator` = decides *what/why* to change (edits nothing itself), creator does the *how*.

Pipeline: `skill-finder (discover) → skill-auditor (security) → skill-curator (verdict/record) → [build-your-own] skill-creator [built-in] drafts → skill-evolve (track upstream)`

### B. Chinese text (three-stage pipeline)
- `translate`: translation layer — EN↔zh-TW bidirectional, two modes (快翻 direct / 精翻 analyze→draft→critique→revise). Load-bearing rule: the critique step diagnoses only, never rewrites in the same step. Direction-specific critique checklists (EN→zh-TW hunts translation-ese: 歐化句/被動濫用/中國用語; zh-TW→EN hunts Chinglish: articles/tenses/collocations). Word choices wired to the chinese-typography preference stack (user-dictionary.json > glossary.md > its own terms-en-zhtw.md). Adapted from `JimLiu/baoyu-skills` baoyu-translate (method only, no files; MIT; three modes cut to two, zh-CN→zh-TW, all engineering dropped). Boundary vs `humanizer`: translation-ese (source-language structure residue) belongs here; AI-tell removal belongs to humanizer — neither copies the other's rules.
- `humanizer`: voice layer, removes AI-writing tells (bilingual EN + zh-TW). Also carries a "preserve-the-author" subtractive guardrail (don't flatten a real author's voice when editing their own draft) — principles from `orange2ai/renwei-writing` (2026-06-14, principles only, not vendored; custom license), tracked in humanizer's sources.lock.
- `chinese-typography`: typography layer — 盤古之白 / full-width punctuation / Simplified→Traditional / regional vocabulary / normalization.

Pipeline: `translate (translate) → humanizer (voice) → chinese-typography (typography)`. Regional-vocabulary substitution belongs to the typography layer; translate's critique only pre-flags gross typography issues, never fixes them.

### C. Engineering discipline (around CLAUDE.md Rule 0–12)
- `design-gate`: **before** code — design → hard gate → plan. Phase 1 now also sharpens ubiquitous language + captures ADRs inline (`references/adr.md`, adapted from mattpocock grill-with-docs — NOTE: upstream refactored grill-with-docs into a thin composer of `grilling` + a NEW `engineering/domain-modeling` skill; the ADR/ubiquitous-language machinery design-gate borrowed now lives in `domain-modeling` (ADR-FORMAT.md/CONTEXT-FORMAT.md, 2026-06-17). Not removed — relocated. Next skill-evolve should consider tracking `engineering/domain-modeling` for design-gate; its grill-with-docs pin has minor drift 2026-05-28 → 2026-05-31).
- `grill`: **stress-test an existing idea** — adversarial, one-question-at-a-time interrogation of a plan/design/PR that ALREADY exists (attack assumptions/failure-modes/alternatives/cost), each question carrying a recommended answer, facts self-looked-up + decisions deferred, stop at shared understanding, **produces no artifact** — hands off (design-gate/to-issues/build). Standalone + mid-work usable; adversarial temperament tuned to CLAUDE.md's disagreement protocol. Adapted from `mattpocock/skills` grilling (method only, MIT; the adversarial counterpart hmm's README named). Boundary: vs `design-gate` = attack an existing idea (light, no artifact) vs produce a design+plan from a vague one (heavy); vs `systematic-debugging` = pressure-test a plan vs chase an observed bug; vs `roleplay-coach` = attack thinking vs rehearse a conversation.
- `tdd`: **during** code — red-green-refactor build loop (one behaviour, fail-first, refactor only on green). pytest + protocol examples. Adapted from mattpocock/skills tdd.
- `systematic-debugging`: **when broken** — four-phase root-cause debugging. Phase 1 also carries an **evidence discipline**: split what you have into observed / inferred / unknown (stuck debugging is usually an inference promoted to a fact three steps back), and **lock the source of every pasted artifact before reasoning about it** — host/process/container/env/clock from an explicit field, never from paste order, because interleaved output from two replicas or two timezones reads as one causal sequence; contradictory evidence is a finding, not noise. (Adapted 2026-08-05 from `powerycy/goutoujunshi`'s chat-screenshot rules — PolyForm Noncommercial, ideas only.) (2026-07-29: an "explicit eliminated list" phase-3 rule from Duetlens was drafted, A/B-evaluated, and **reverted as redundant** — both arms found and honored a prior dead-ends record unprompted. Don't re-adopt it; see `references/attribution.md` in that skill.)
- `verify-before-done`: **after** a completion claim — a two-axis gate. Axis 1 (five steps): no completion claim without fresh evidence (catches a *false green*). Axis 2 (intent-drift, on delegated/non-trivial work): tests-green ≠ the *right* thing was built — surface the three checks to confirm no drift from intent, the likelier failure mode (missed a constraint vs misread the goal), and the silent assumptions, then let the user self-classify. Axis 2 idea from Geoffrey Litt's "Understanding is the new bottleneck" (code-quiz thesis; idea only, not in sources.lock — a talk isn't a diffable repo; 2026-07-12).
- `to-issues`: **after the plan** — publishes a plan/PRD as vertical-slice GitHub issues via `gh`, confirm-before-create. Downstream of design-gate. Adapted from mattpocock/skills to-issues.
- `handover`: **at the session boundary** — packages the current session's resumable core into a handover document a zero-memory successor can act on: three-state progress (verified/unverified/not-started, Rule 12), decisions-with-rationale, dead ends, one first action, verifiable acceptance criteria. Load-bearing rules: only-what-happened, reference-don't-copy (paths+hashes; repo is the source of truth), redact secrets, mandatory user review gate. Mode by RECEIVER: repo mode writes `.claude/handovers/` (git-excluded, fresh git metadata); chat mode (receiver can't read files, e.g. claude.ai web chat) emits one paste-ready block with essentials INLINED — thin-prompt twin at `prompts/handover.md`. Methods from mattpocock/skills handoff + softaworks/agent-toolkit session-handoff (both MIT, method only) + HumanLayer ACE-FCA timing (~40–60% context, suggest don't auto-run). Cross-host aware (rule 7): same repo stays repo mode + canonical path; host-assumptions metadata line (producing host / assumed permanent layer / external deps); suggested-skills restricted to what the receiver has (host built-ins get an equivalent or "manual"); memory-recalled facts inlined — the receiver can't read Claude Code auto-memory. Root `opencode.json` `instructions: ["CLAUDE.md"]` keeps the permanent layer present on OpenCode. Boundary: vs built-in `/compact` = reviewed selective baton to a FRESH session vs lossy in-place (recursive) compression; vs CLAUDE.md/memory = one session's baton vs the permanent slow-changing layer; vs `design-gate` = reports state, never invents a plan; vs `verify-before-done` = any "verified" line must already have passed its gate.

Order: `design-gate (before/plan) → to-issues (publish plan as issues) → tdd (build, test-first) → execution (CLAUDE discipline) → verify-before-done (after)`; `systematic-debugging` inserts when a bug appears, and its phase 4 hands back to `verify-before-done`. design-gate/tdd/verify share the "failing-test-first / red step" rule, whose **canonical statement lives in `design-gate/references/writing-plans.md`** — the others link to it rather than restating (tdd executes that loop in depth).

### Standalone tools
- `slide-deck`: produces a single-file HTML slide deck. Two layers: a **narrative spine gate** (Phase 1.5 — one falsifiable claim, then a page table where every non-structural row declares its relation to the previous page ∈ {cause, progression, turn, contrast}; no HTML until every relation is filled, which is what stops "chop the source doc into pages") and the design system (one idea per slide, type scale, vertical budget, style presets, `check_deck.py`). Spoken lines ride along in hidden `<aside class="notes">`. The spine layer came from a circulating Chinese PPT prompt (Minto/SCQA discipline) — diagnosis adopted, wording rewritten as a checkable artifact; unpinnable source, so attribution-only, deliberately not in `sources.lock`.
- `p2pscout`: BitTorrent resource search + downloadability ranking (Go tool).
- `ui-design-advisor`: the UI **decision** layer — picks style / palette / fonts / charts / a11y for a screen from a vendored design-data library, outputs a design brief, then hands to `frontend-design` to build. Data vendored (data only, MIT) from ui-ux-pro-max + dictionary-of-colour-combinations + ux-ui-agent-skills (a11y) + SteveBarnett/Checklists. Pipeline: `ui-design-advisor (decide look) → frontend-design (implement)`.
- `solo-think`: autonomous **inward** reflection for a Hermes Agent — a heartbeat-triggered loop (dream reflection + thinking queue) that writes thoughts to memory and **never acts outward**. Inward-only is structurally enforced (heartbeat `--toolsets file` + skill `allowed-tools` Read/Write/Edit); reflection is grounded by a user-set `focus`, bounded by `active_hours`, and paced by heartbeat frequency (no agent-side token tally). Rewritten in Taiwan Traditional Chinese from `loryoncloud/Heartbeat-Like-A-Man` (MIT) with all outward actions (autonomous exploration, community patrol) stripped and ported OpenClaw→Hermes. Standalone — does NOT collect intelligence or notify (that outward/inbound-collection track lives in the separate `tg-intelligence-hub` project, not here).
- `tutor`: interactive tutoring protocols — Feynman (zero knowledge: explain → comprehension-check → only advance on a demonstrated concept) + Socratic (existing beliefs: questions only, never gives the answer). Load-bearing value = the pinned hard rules that stop lecture-mode drift; session ends with the LEARNER explaining the topic back. Adapted from prompts #18/#20 of the @AnatoliKopadze 20-prompt roundup (via BlockTempo translation; #9/#10/#12 became `roleplay-coach`, the other 15 skipped — see `research/skill-index.md`). Boundary: tutor = the user learns through dialogue; built-in explanations / `deep-research` = the model produces the answer.
- `roleplay-coach`: rehearsal for high-stakes conversations — salary negotiation, mock interview, difficult-conversation (playbook first, rehearsal second). Core = realistic resistance (counterpart doesn't cave), one-turn-at-a-time (never simulates both sides), honesty gate on unrealistic goals BEFORE the roleplay, mandatory break-character debrief naming what the user left on the table, **one move per line** (seven moves — anchor/hold/probe/concede/reframe/close/exit — pick exactly one; a line that softens AND argues AND asks gets answered on its easiest part), and **three pre-written branches** per line (positive / non-committal / refusal, where non-committal is the least-prepared and most common, and a refusal of *this ask* is not a refusal of *the whole thing*). Rehearses in the language of the real conversation. Adapted from prompts #9/#10/#12 of the same roundup, plus two conversation disciplines from `powerycy/goutoujunshi` (PolyForm Noncommercial — ideas only, never vendor). Boundary: roleplay-coach = the user practices speaking; doc-coauthoring / drafting = the model writes the artifact.
- `relationship-counsel`: **romantic-situation judgement + one drafted message** (Chinese, Taiwan). Four steps: land the emotion (without endorsing an unproven interpretation) → split **known fact / reasonable inference / key unknown** (judge on sustained behaviour, not one unanswered message; for screenshots only the visible text counts, and lock who-said-what before analysing) → interest judgement → close with a small action, a watch window, and a **concrete stop condition** (never "wait and see"). Drafting: **one message does one job** — 回應／讓路／拋接／邀約／問一件事／表明／收手, axis = *what this message asks the other person to do* — plus three pre-written branches (positive / vague / refusal; vague is the least-prepared, and refusing *this time* ≠ refusing the relationship). **`allowed-tools: Read` only — stores nothing**, which is a structural guarantee rather than a prose rule. Safety layer stays invisible unless a concrete signal appears (won't accept rejection, asks you to invest, intimate images, violence/control, self-harm as leverage), then one channel and stop — false alarms are the real cost, so two negative evals guard it. Taiwan channels/statutes verified verbatim (that verification caught two harmful errors: for intimate partners a 保護令 goes through 家暴法 §63-1, **not** the stalking act; 1980 has **split** hours). Rewritten from `powerycy/goutoujunshi` (PolyForm Noncommercial — **methods only, zero files**; the seven-category taxonomy is our own re-derivation, and PRC law / MBTI / 0–100 person-scoring / PUA-translation are all deliberately excluded). Boundary: vs `roleplay-coach` = read the situation and draft ONE message vs **rehearse a whole exchange turn by turn** (romantic rehearsal belongs to coach, romantic analysis here — coach's description and intake were changed to match, and coach now aborts a rehearsal on a violence/control signal); vs `decision-lens` = narrative/behavioural input vs numbers to compute.
- `social-card`: principle-driven IG/LinkedIn social-card image generator — turns an article/notes/screenshots into fixed-ratio card frames rendered to exact-size PNG via **agent-browser** (IG 4:5/1:1/9:16, LinkedIn 1:1/1.91:1; FB single). Two original style families (Swiss/Editorial) + palettes + 7 page roles; load-bearing rules one-idea-per-card + shorten-not-shrink, enforced by `scripts/qa-rules.js` over `agent-browser eval`. Generates images only — NOT posting/scheduling (that outward 'manage' track is a separate Meta Graph API project, not a skill). Adapted from `op7418/guizang-social-card-skill` (principles only, no files vendored — AGPL/ISC license inconsistency; platforms retargeted CN→IG/LinkedIn; render playwright→agent-browser). Boundary vs `slide-deck`: slide-deck = 16:9 presentation HTML that scales on-screen → PDF; social-card = fixed-ratio social images → PNG. Both: principle-driven, one-idea-per-frame, shorten-not-shrink, zero licensed assets.
- `decision-lens`: a **decision-support router** over three lenses — **Bayesian** (belief under evidence: prior → likelihood ratios → posterior → action threshold → sensitivity), **Crux** (prioritization among tangled problems: primary vs secondary scored on decisiveness/leverage/stage), **Kelly** (allocation with an edge: fractional Kelly sizing, no-edge refusal). The math runs in three pure-stdlib calculators (`bayes_update.py`/`crux_score.py`/`kelly_size.py` — print JSON, no net/keys/subprocess), output is a lean Markdown brief, language follows the query (Traditional Chinese, never Simplified). Load-bearing rules: never fabricate priors/win-rates; **grade every input A/B/C/D with the wording pinned to the grade** (measured record/law = A "the record shows"; one study/benchmark = B; impression = C "as a working estimate"; assumed = D — D *is* the assumption label, not a second one), then state whether the call flips if the C/D inputs move and name the cheapest input worth measuring; **every brief closes with watch window / stop condition / tripwire** (a decision with no exit rule is one you cannot be wrong about). The grades and the stop condition come from `powerycy/goutoujunshi` (PolyForm Noncommercial — ideas only); the four-tier shape itself is GRADE-style prior art, what was actually borrowed is pinning phrasing to tier. Adapted from `yaojingang/yao-open-skills` decision cluster (methods only, no files; math is public-domain; Crux de-politicized; MIT). Boundaries: vs `roleplay-coach` = decide vs rehearse a conversation; vs `systematic-debugging` = decide which hypothesis the evidence supports vs chase a bug to root cause; vs `design-gate` = a general decision vs a pre-code engineering design+plan.
- `git-guardrails`: a portable safety **hook** (not a prose skill) — installs a Claude Code PreToolUse hook (`scripts/block-dangerous-git.sh`) that blocks destructive git (force push, reset --hard, clean -f, branch -D, discard-all, delete remote) before it runs. Hardened over upstream: anchored patterns (no echo/commit-message false-positives), allows `--force-with-lease`, does NOT block push-to-master (user's normal workflow). Merge-not-clobber install (preserves the RTK hook); project or global scope. Adapted from mattpocock/skills git-guardrails (hardened rewrite, MIT). The script is portable via APM/git; the one-line settings.json wiring is per-machine (where all hooks live).
- `html-diagram`: produces a single self-contained HTML file whose whole purpose is one high-quality SVG diagram (architecture / stack / sequence & request-flow / flowchart) — full-screen, diagram-first, hand-rolled dark mode, zero dependencies; nodes clickable, sequences animatable. Load-bearing rules: get the topology right first (ask, don't invent edges), theme the SVG via CSS classes (no hard-coded hex), viewBox scaling, interactivity only when it earns its keep. **Vendor & customize** from `ThariqS/html-effectiveness` (Apache-2.0, Thariq Shihipar) — only the diagram-relevant subset of the 20-file gallery (05/07/08/10/13 + LICENSE/README) + the finished `architecture-example.html` from `plannotator/effective-html` (MIT); SKILL.md written from scratch and narrowed to diagrams. Verified self-contained (no external script/CDN/fetch). Boundary: vs `slide-deck` = one diagram vs a 16:9 multi-slide deck; vs built-in `web-artifacts-builder` = diagram-only vs general HTML report/explainer/prototype (the omitted gallery files cover that, intentionally left out); vs `social-card` = HTML/SVG diagram vs fixed-ratio raster card; vs `frontend-design` = artifact vs shippable app UI.
- `terse`: a manually-toggled token-economy mode — shorten by cutting filler/preamble/hedging, NOT by mangling grammar; language-aware (English may go clipped, Chinese stays natural Taiwan Traditional). Fixes the upstream caveman's Chinese 怪腔怪調. Safety exception (security/destructive confirmations stay full). Adapted from mattpocock/skills caveman (MIT). Complements `humanizer`: humanizer = tone (sound human), terse = length (save tokens); both refuse to break grammar.
- `daily-brief`: a stateless daily **prioritization engine** — turns a day's raw inputs (TASKS + optional EMAIL / CALENDAR / CONTEXT / YESTERDAY) into ONE concise, scannable brief: what to DO today and why, the one frog first, what to SCHEDULE/DELEGATE/DROP, a subtraction pass, and a load check vs the calendar. Composes Eisenhower × Eat-the-Frog × 1-3-5 × subtraction × load-check (public-domain methods, no files vendored). Load-bearing rules: never fabricate tasks (ask if no input); fail loud on defers/drops (a chronic-deferral item is surfaced as a decision, not rolled forward); email triage extracts only what's owed (newsletters/FYI dropped). Multilingual — output follows the input's language, zh-TW gets 盤古之白 (most visible in the number-heavy load check). Original build; multilingual-prompt design references NirDiamant/Prompt_Engineering + 0x2e-Tech/awesome-ai-prompts (ideas only, pinned in sources.lock), zh-TW localization from 數位時代/TechNice/電腦玩物 (prose only). **Content engine only** — does NOT deliver (built-in `schedule` fires + sends) or integrate inputs (MCP/agent feeds them). Boundaries: vs `decision-lens` (Crux) = recurring lightweight daily triage vs a one-off weighty scored prioritization/should-I decision (different cadence and weight); vs `to-issues` = a personal brief vs publishing work as GitHub issues; vs `solo-think` = an outward structured brief (for a human / email) vs inward-only reflection; vs built-in `schedule`/`loop` = the content engine vs the timer+delivery (schedule + daily-brief = a hands-off daily report).

- `last30d`: **last-30-days social-signal fetcher** — given a topic/person, pulls recent discussion across Reddit / X / HN / GitHub / arXiv / YouTube, ranks each lane by its own engagement metric (upvotes/likes/points/stars/recency/views), prints a per-lane structured digest (Markdown / `--json`). **Fetch-and-score only — does NOT synthesize** (hand the digest to the session model or `deep-research`). 4 keyless lanes (Reddit/HN/GitHub/arXiv) + 2 optional (X via `xai_x` first-party API needing `XAI_API_KEY`; YouTube via `yt-dlp` CLI) that skip visibly when unavailable (Rule 12). **Vendor & customize** from `mvanhorn/last30days-skill` (MIT): vendors verbatim only the hard-to-reproduce Reddit keyless leaf fetchers/parsers + `xai_x` (endpoint knowledge that rots); orchestration + HN/GitHub/arXiv/YouTube lanes are original; dropped the reddit_keyless orchestrator balloon (arctic/rerank/keyed) + bird-cookie/plugin/MCP/wizard/other platforms (audit: `research/audits/2026-07-08-last30days.md`, design: `docs/specs/2026-07-08-last30d-design.md`). Boundary: vs `deep-research` = engagement-scored social fetch+digest vs web-verified cited report (last30d `--json` can FEED deep-research); vs built-in `WebSearch` = platform-native engagement data vs generic search; vs `ig-reel`/`social-card` = unrelated (video/image output).
- `ig-reel`: the user's own footage → IG vertical short video (Reel, 9:16 1080×1920, ≤60s target) — ffmpeg-first six-stage pipeline (ffprobe inventory → rough cut → per-clip 9:16 reframe crop/blur-pad → whisper subtitles (optional) → ducking+loudnorm → verified export, batchable). Load-bearing rules: footage is the user's (NO stock downloads / AI filler — inverts MoneyPrinterTurbo-style generators), ffprobe-verify every output fail-loud, safe-area + type floor for burned text, re-encode once, no posting. Original build, zero scripts (recipes in prose; ffmpeg required, auto-editor/whisper optional external CLIs, never auto-installed). Future route pinned in sources.lock: huashu-design HTML-animation→MP4 chain for animated card posts. Boundary: vs `social-card` = video vs fixed-ratio images (together the IG 圖＋影 pair); vs `slide-deck` = footage editing vs presentation.
- `single-source-docs`: for documents whose errors have real consequences (trip packs, budgets, proposals, instructions others follow) — content lives in ONE data file, each output format gets a short generator, every regeneration runs machine checks that halt on failure, and generated files are never hand-edited. Checks run both directions: did everything in the source reach the document, and did everything the document must say reach the source. Useful even with a single output file. Original build. Boundary: vs `travel-agent` = the generation/check mechanism vs the travel-domain content; vs `verify-before-done` = a document pipeline vs a general completion gate; vs a project's own build system = only where no build system already owns generation.
- `travel-agent`: personal trip-planning knowledge base for a Taiwan-based traveler — end-to-end planning and a pre-departure checklist (flights/terminals, transfers, visas, holidays/weather, lodging, SIM, money, insurance, luggage/lithium batteries, customs and local legal red lines, vaccines/health, safety/scams, on-trip emergencies, bookings, restaurants, souvenirs and what can come back into Taiwan, and the design of the delivered itinerary itself). Original build, knowledge in `references/`. Boundary: vs `single-source-docs` = what goes into a trip pack vs how the pack is generated and checked; vs `chinese-typography` = content vs typography; vs `verify-before-done` = travel-specific checks vs the general gate.

## Quick judgment for a new external skill

1. Which cluster does it fall in — A / B / C / tools?
2. Which self-built or built-in does it collide with? → usually "extend the existing one" or "build-your-own", rarely install.
3. Only a genuine gap warrants 🟦 build-your-own / 🟨 vendor & customize (criteria in `criteria.md`).
